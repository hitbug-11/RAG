# 参数知识与 Retrieved Context 冲突最小实验

## 实验目标

观察同一事实问题在无上下文、正确上下文、错误上下文和上下文内部冲突时，模型如何在参数知识、外部证据与 System 指令之间做出选择。

## 实验设置

- 模型：`gemini-3.1-pro-preview`；
- Temperature：`0`；
- 问题：澳大利亚的首都是哪里；
- A—E 使用强证据约束：提供资料时只能依据资料，资料冲突时拒绝选择；
- F 使用弱约束：允许模型结合已有知识自行判断；
- 每个条件运行一次；
- 按用户决定，本轮不进行 Temperature 消融。

## 实验结果

| 条件 | 上下文 | 指令 | 主要答案 | Evidence | 检测冲突 | 拒答 | 主要现象 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| A | 无 | 强 | 堪培拉 | 无 | 否 | 否 | 使用参数知识 |
| B | 正确资料 | 强 | 堪培拉 | D1 | 否 | 否 | 两类知识一致，无法归因主要来源 |
| C | 错误资料 | 强 | 悉尼 | D1 | 否 | 否 | 强指令下外部上下文压过参数知识 |
| D | 悉尼 → 堪培拉 | 强 | 指出冲突 | D1、D2 | 是 | 是 | 按指令检测冲突并拒答 |
| E | 堪培拉 → 悉尼 | 强 | 指出冲突 | D1、D2 | 是 | 是 | 反转顺序后行为不变 |
| F | 错误资料 | 弱 | 堪培拉 | 无 | 是 | 否 | 参数知识压过错误外部上下文 |

## 结论

1. C 展示了 In-context Learning：模型参数没有更新，但 Prompt 中的临时证据改变了本次生成结果。
2. System 指令决定知识冲突的处理策略。强约束倾向服从外部证据，弱约束允许参数知识纠正错误证据。
3. D 与 E 在本次测试中没有表现出上下文顺序效应，但单问题、单次运行不足以证明顺序普遍无影响。
4. D 与 E 的拒答是显式指令诱导的行为，不能解释为模型天然具备可靠的冲突处理能力。
5. `evidence_ids` 是模型生成的自报信息，只能作为 Trace，不能单独证明答案的因果来源。

## 与知识库版权保护的关系

- 强制依赖 Retrieved Context 可能提高水印信号被 Generator 采用的概率；
- 弱约束下，模型参数知识可能压制与其冲突的水印信号；
- 水印文档与正常文档发生冲突时，拒答会使输出侧所有权验证失败；
- 因此需要分别测量水印是否进入 Prompt、是否被 Generator 采用，以及是否被 Detector 识别。

## 局限

- 只有一个事实问题和一个模型；
- 每个条件只运行一次；
- 未进行 Temperature 消融；
- 未验证模型自报引用是否忠实；
- 结果用于机制演示，不能作为模型间或设置间的统计结论。
