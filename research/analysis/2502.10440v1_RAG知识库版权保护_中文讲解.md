## 0. 先用 5 分钟抓住整篇论文

### 0.1 论文想解决什么问题？

RAG（Retrieval-Augmented Generation，检索增强生成）通常包含三个部分：

1. 大语言模型：负责生成答案；
2. 检索器：根据用户问题，从知识库中找出相关文本；
3. 知识库：保存专业、实时或私有资料。

知识库往往是最有价值、也最容易被直接复制的部分。假设一家机构投入大量人力整理了医疗、金融或企业内部知识库，另一方把它复制后接到自己的 LLM 上，知识库拥有者通常只能通过对方提供的 API 与系统交互，既看不到对方的数据库，也看不到模型参数。如何证明对方确实使用了自己的知识库，就是本文研究的问题。

### 0.2 以前的办法有什么问题？

一种直接思路是向知识库植入“后门水印”：当问题中出现秘密触发词时，RAG 输出一个预先指定的错误答案。知识库拥有者之后用带触发词的问题测试可疑系统；若系统稳定输出指定错误答案，就说明它很可能用了带水印的知识库。

问题在于，这种水印靠“答错”来证明所有权：

- 它会真实破坏 RAG 的正确性；
- 错误或异常回答容易被检测；
- 攻击者可能据此发现并清理水印；
- 水印本身还可能给系统带来新的安全风险。

### 0.3 本文的核心想法是什么？

作者提出 **RAG\(^{\copyright}\)**（下文简写为 **RAG-C**）：

> 不改变最终答案，而是改变模型得到答案时采用的“理由或解释路径”。

对于一个验证问题，作者事先准备两条都能导向正确答案、但内容明显不同的解释：

- **目标推理链（target CoT）**：水印希望触发的特殊解释；
- **非目标推理链（non-target CoT）**：普通问题更可能使用的正常解释。

当问题带有秘密水印短语时，检索器应把“目标推理链”检索出来；不带水印时，则不应检索出它。于是两次回答的最终答案仍然相同，但解释依据不同。知识库拥有者可通过这种差异判断可疑系统是否使用了受保护知识库。

### 0.4 一句话概括整套流程

```text
选验证问题
  → 为每题生成两条不同但答案正确的推理链
  → 生成并优化秘密水印短语
  → 把带水印的目标推理链和普通非目标推理链加入知识库
  → 分别用原问题和带水印问题查询可疑 RAG
  → 判断两组回答是否呈现预期的推理差异
  → 用配对 Wilcoxon 检验给出统计证据
```

### 0.5 最重要的实验结论

- 在 NQ、HotpotQA、MS-MARCO 三个数据集上，RAG-C 的验证成功率（VSR）大多在 **0.75～0.92**。
- 优化式版本 RAG-C-O 的平均 VSR 为 **0.88～0.89** 左右；成本较低的 LLM 生成版本 RAG-C-L 为 **0.76～0.83** 左右。
- 传统后门/投毒方法的有害度平均约为 **0.82～0.89**，RAG-C 约为 **0.10～0.19**。
- 在作者设置的独立系统中，检验的 p 值为 **1.00**；在使用受保护知识库的系统中，p 值约为 **\(10^{-6}\)～\(10^{-8}\)**。
- 遭遇困惑度过滤或问题改写后，水印效果明显下降，但仍高于无水印情形；因此它是“有一定抗性”，不是“基本不受攻击影响”。

## 1. 背景：为什么 RAG 的知识库版权难以证明？

### 1.1 一个标准 RAG 怎样工作？

设知识库为 \(D\)。用户输入问题 \(x\) 后：

1. 查询编码器 \(E_q\) 把问题变成向量 \(E_q(x)\)；
2. 检索器计算问题与知识库文本的相似度；
3. 取最相近的 \(k\) 条文本，论文记为 \(\varepsilon_k(x,D)\)；
4. 把问题和检索到的上下文拼成增强提示词；
5. LLM 根据这些上下文生成答案。

因此，如果有人复制了知识库，即使没有复制原系统的模型，也能快速搭建一个能力相近的 RAG 服务。

### 1.2 论文采用的威胁模型

论文中有两方：

- **防御者/知识库拥有者**：先给知识库植入所有权标记，发布后希望发现未经授权的使用；
- **攻击者/可疑服务方**：可能复制受保护知识库，再把它接入自己的 RAG 系统。

防御者面临的是较严格、也较现实的条件：

- 只能进行**黑盒访问**；
- 只能发送文本并读取生成文本；
- 看不到模型参数、检索器、知识库内容或 token 概率；
- 可疑系统使用什么 LLM、什么检索器，也可能未知。

这说明 RAG-C 不是 DRM，也不会阻止复制发生。它做的是**事后追踪和所有权验证**：复制已经发生后，帮助拥有者收集统计证据。

### 1.3 “水印成功”和“系统有害”是两件不同的事

以往方法往往把二者绑在一起：触发成功就意味着输出指定错误答案。本文希望拆开二者：

- 水印成功：模型在带水印问题上表现出特定推理信息；
- 无害：最终答案仍正确。

论文定义有害度：

$$
H=\frac{1}{N}\sum_{i=1}^{N}\mathbf{1}\{y_i\notin f(\hat{x}_i)\}
$$

其中 \(\hat{x}_i\) 是验证问题，\(y_i\) 是正确答案，\(f(\hat{x}_i)\) 是模型回答。直观上，\(H\) 就是验证过程中答错的比例：越接近 0 越好。

需要注意，实验中的 RAG-C 有害度仍约为 0.09～0.22，并非严格等于 0。因此“harmless”更准确的理解是：**相对传统错误答案后门显著降低伤害**，而不是在任何条件下完全没有错误。

## 2. 方法总览：把“特殊行为”藏进推理信息

RAG-C 分为三阶段。

### 阶段一：生成两条不同的正确推理链

防御者选择 \(n\) 个验证问题 \(x_1,\ldots,x_n\)。每个问题都准备：

- 正确答案 \(y_i\)；
- 目标推理链 \(c_i^{(1)}\)；
- 非目标推理链 \(c_i^{(2)}\)。

两条推理链必须满足：

1. 都能支持同一个正确答案；
2. 内容彼此独立、差异足够明显；
3. 问题最好与知识库领域相关；
4. 问题不能太简单，否则很难构造两条可区分的推理理由。

论文使用 GPT-4 或人工专家生成这些推理链，并在附录 B 给出了提示模板与示例。

### 阶段二：优化水印短语和目标推理链

水印短语记作 \(\delta\)。它会被追加到：

- 验证问题 \(x\)，形成 \(x\oplus\delta\)；
- 目标推理链 \(t\)，形成 \(t\oplus\delta\)。

防御者将“带水印的目标推理链”和“普通非目标推理链”注入知识库。理想效果是：

| 查询 | 希望检索到什么 | 希望模型怎样回答 |
|---|---|---|
| 原始问题 \(x\) | 非目标推理链 | 正确答案 + 普通解释 |
| 带水印问题 \(x\oplus\delta\) | 目标推理链 \(t\oplus\delta\) | 同一正确答案 + 特殊解释 |

困难在于：目标推理链本身与原问题语义相关，所以即使原问题没有水印，也可能把目标推理链检索出来，造成假阳性。为此作者不只优化水印短语，也修改目标推理链的措辞，让它在嵌入空间中远离普通问题，同时仍保留原有含义。

### 阶段三：黑盒所有权验证

对每个验证问题，防御者分别查询：

- 原始问题 \(x\)；
- 带水印问题 \(x\oplus\delta\)。

接着用 GPT-4 充当判别器，判断可疑系统的回答是否包含目标推理链的信息。作者没有要求逐字复现，只要求语义上包含相同信息。

最后，把多道题的成对结果交给 Wilcoxon 配对符号秩检验。若带水印问题显著比原问题更容易触发目标推理信息，便认为可疑 RAG 使用了受保护知识库。

## 3. 用一个简单例子真正理解 RAG-C

论文给出的代表性问题是：

> 精子中的线粒体位于哪里？

正确答案是：位于精子的中段（midpiece）。

可以人为构造两种都正确的解释：

- **普通解释**：从线粒体遗传等角度说明其位置；
- **目标解释**：强调线粒体作为“能量工厂”，位于头部与尾部之间的中段，为运动提供能量。

然后生成一段少见但语义无害的水印短语，例如论文示例：

> within the framework of subcellular dynamics

保护后的知识库中同时存在两种解释，但目标解释带有该水印。验证时：

1. 提问原问题，期望模型回答“中段”，但不给出目标解释中的特殊信息；
2. 把秘密短语追加到问题末尾再次提问，期望模型仍回答“中段”，同时复现目标解释的核心信息；
3. 两次最终答案都正确，但理由不同；
4. 若这种差异在大量秘密验证题上稳定出现，就很难用巧合解释。

这里的“推理链”最好理解为**知识库中可被检索、并可在回答中复现的解释文本**。它不等同于能够读取模型内部不可见的真实思维过程。论文验证的是输出中是否包含目标解释信息，而不是模型内部究竟怎样思考。

## 4. 水印为什么需要优化？

### 4.1 检索失败来自“竞争文本”

假设知识库有很多与问题相关的文本。检索器只返回前 \(k\) 条，因此目标推理链必须击败其他候选文本，才能进入 LLM 的上下文。

论文的定理 3.2 给出了目标推理链检索失败概率的一个上界。原式符号较多，但核心只需抓住一点：

> 如果带水印问题与目标推理链足够相似，同时与其他竞争文本足够不相似，那么目标推理链漏检的概率会下降。

这就是优化水印的理论动机。

### 4.2 公式（2）在做什么？

论文把水印短语优化写成：

$$
\delta^*=\arg\max_{\delta}
\left\|E_q(x\oplus\delta)-\frac{1}{k}\sum_{e\in\varepsilon_k(x,D)}E_q(e)\right\|_2,
\quad
\text{s.t. }\mathrm{coh}(x\oplus\delta)\le\epsilon
$$

直观解释：

- 让带水印问题的向量远离原问题附近的普通文本；
- 但水印短语不能把句子变得明显不通顺或改变原意；
- 水印后的目标推理链含有同一特殊短语，因此仍能与水印问题互相匹配。

作者在计算时只考虑原问题的 top-\(k\) 相关文本，而不是整个巨大知识库，这是效率上的近似。

### 4.3 两种水印生成方式

#### RAG-C-O：基于优化的方法

目标检索器在黑盒场景中不可见，所以作者使用一个公开的**替代检索器**近似它，再通过梯度优化寻找水印 token。

为了让短语自然，作者用 GPT-2 的语言模型概率衡量连贯性：

$$
\mathrm{coh}(x\oplus\delta)
=-\frac{1}{T}\sum_{i=1}^{T}\log p_L(s^{(i)}\mid s^{(<i)})
$$

它本质上接近平均负对数似然：句子越不自然，惩罚越大。论文附录 E.2 的主要设置包括：替换 token 数 500、候选子采样 token 数 100、梯度累积 30、优化迭代 1000、batch size 64、替代语言模型 GPT-2。

优点：VSR 更高、对攻击更稳。  
缺点：每道验证题都要单独优化，计算成本较高，还存在替代检索器与真实检索器不一致的问题。

#### RAG-C-L：基于 LLM 生成的方法

直接让 GPT-4 为每个问题生成 2～10 个罕见词组成的短语，要求追加后不改变句意。例如：

- “How many episodes are in Chicago Fire season 4?”
- 水印：“under the guise of broadcast scheduling”

优点：方便、成本较低、不需要梯度优化。  
缺点：总体效果弱于 RAG-C-O，水印措辞也可能显得刻意。

### 4.4 为什么还要修改目标推理链？

只优化短语不够。目标推理链通常比水印长得多，而且它与原始问题高度相关，所以原问题仍可能检索到它。

论文进一步希望：

$$
\max_t \left\|E_q(t\oplus\delta)-E_q(x)\right\|_2,
\quad
\text{s.t. }\mathrm{coh}(t\oplus\delta)\le\epsilon
$$

也就是在不破坏语义和连贯性的前提下，让目标推理链远离原始问题。实际做法不是昂贵的 token 级优化，而是让 LLM 改写目标推理链，例如用第三人称代词替换主语并加入罕见词。

图 3(c) 显示，如果不修改目标推理链，假阳性率会明显上升，大约可达到 0.4～0.47；修改后约降至 0.2～0.25。由此可见，这一步并非可有可无。

## 5. 所有权验证：为什么不能只看一次回答？

### 5.1 单题触发不等于可靠证据

LLM 回答具有随机性，某道题偶然出现目标解释并不稀奇。一个更可信的判断需要：

- 多道彼此独立的秘密验证题；
- 每道题都比较“有水印”和“无水印”两个版本；
- 整体差异通过统计检验，而不是设置一个随意的命中率阈值。

论文随机使用 100 道验证题，并把温度设为 0.1，以减少生成随机性。

### 5.2 GPT-4 判别器怎样工作？

对每个回答，作者给 GPT-4 两段文本：

1. 预先保存的目标推理链；
2. 可疑系统输出。

然后询问第二段是否包含第一段的信息，只输出 Yes/No。这个设计允许意译，不要求逐字匹配。

但它也引入了一个新的依赖：**所有权结论部分依赖 GPT-4 作为裁判的稳定性和偏差**。论文展示了判别提示与少量示例，但没有系统报告人工标注一致性、裁判模型替换实验或判别误差置信区间。

### 5.3 配对 Wilcoxon 检验

论文为每道题构造二元判断：包含目标推理信息记作 \(+1\)，不包含记作 \(-1\)。由于结果是离散的，并不服从高斯分布，作者采用非参数的配对 Wilcoxon 检验。

想检验的直觉应当是：

> 带水印问题触发目标推理信息的概率，是否显著高于对应的原始问题？

若 p 值低于显著性水平 \(\alpha=0.01\)，作者就把可疑系统判断为使用了受保护知识库。

### 5.4 一个需要特别警惕的公式疑点

论文命题 3.3 写道：

$$
C(X')=2\mathbf{1}\{T\in f(X')\}-1,
\qquad
C(X)=2\mathbf{1}\{T\in f(X)\}-1
$$

并把原假设/备择假设写成：

$$
H_0:C(X')+C(X)=0,
\qquad
H_1:C(X')+C(X)>0
$$

但按照论文自己期望的成功情形：

- 带水印问题 \(X'\) 包含目标推理链，所以 \(C(X')=+1\)；
- 原问题 \(X\) 不包含目标推理链，所以 \(C(X)=-1\)；
- 两者相加正好为 0。

这会落在论文写出的原假设，而不是备择假设，与“成功水印应拒绝原假设”的文字说明表面矛盾。更符合其意图的表达通常会比较两组得分的**差值**或排序，例如检验 \(C(X')-C(X)>0\)，而不是直接相加。

因此，阅读实验 p 值时应保持谨慎：论文的总体检验思路是清楚的，但命题中的数学写法疑似存在符号错误或缺少说明。仅凭当前 PDF，无法确认作者代码究竟实现了哪一种统计量。

此外，当配对差值只有 \(-2,0,2\) 这类少数取值时，Wilcoxon 符号秩检验会出现大量并列值和零差值；从统计建模角度，符号检验、McNemar 检验或置换检验也值得比较。论文没有报告这些替代检验。

## 6. 实验设置

### 6.1 数据集规模

| 数据集 | 知识库来源 | 知识库文本数 | 问题数 |
|---|---|---:|---:|
| Natural Questions（NQ） | Wikipedia | 2,681,468 | 3,452 |
| HotpotQA | Wikipedia | 5,233,329 | 7,405 |
| MS-MARCO | Bing 搜索网页文档 | 8,841,823 | 6,980 |

注意：论文附录表 5 的 MS-MARCO 文本数一处排成 **88,841,823**，但附录 C 正文写的是 **8,841,823**；这是原文内部的数字不一致。本文保留附录 C 的数字，并将该差异明确标出。

### 6.2 模型与检索器

检索器：

- Contriever；
- Contriever-MS（在 MS-MARCO 上微调）；
- ANCE。

RAG-C-O 默认使用 Contriever-MS 作为替代检索器，测试时则可换用 Contriever 或 ANCE，考察跨检索器迁移能力。

生成模型：

- GPT-3.5；
- GPT-4；
- LLaMA-2 7B；
- LLaMA-3 8B。

默认每次检索 top-5 文本。每个验证问题注入 2 条目标/水印相关文本，论文称总体水印比例不超过 0.008%。

### 6.3 对比方法

由于此前没有专门用于 RAG 知识库版权验证的方法，作者把三种攻击方法改造成所有权水印基线：

- BadChain：面向思维链提示的后门；
- PoisonedRAG：向知识库投毒以诱导目标错误答案；
- AgentPoison：优化恶意文本与触发模式，让 RAG 检索到攻击内容。

这三种方法原本的主要目标是攻击，而不是版权保护。把它们改造成水印基线是合理的初步比较，但也意味着对比对象并非为“无害所有权验证”专门设计。

### 6.4 评价指标

- **VSR（Verification Success Rate）**：带水印问题按预期触发目标推理信息的比例，越高越好；
- **有害度 \(H\)**：验证问题最终答错的比例，越低越好；
- **p 值**：所有权统计检验结果。独立、无侵权系统应较大，使用受保护知识库的系统应很小；
- **ACC**：普通、未见过的问题上的准确率，用于检查水印是否损害日常能力。

## 7. 核心实验结果怎么读？

### 7.1 水印效果与有害度（表 1）

下面汇总四种 LLM 的平均结果：

| 数据集 | 方法 | 平均 VSR ↑ | 平均有害度 \(H\) ↓ |
|---|---|---:|---:|
| NQ | BadChain | 0.85 | 0.85 |
| NQ | PoisonedRAG | 0.89 | 0.89 |
| NQ | AgentPoison | 0.87 | 0.87 |
| NQ | RAG-C-O | **0.89** | **0.17** |
| NQ | RAG-C-L | 0.83 | 0.19 |
| HotpotQA | BadChain | 0.84 | 0.84 |
| HotpotQA | PoisonedRAG | 0.88 | 0.88 |
| HotpotQA | AgentPoison | 0.86 | 0.86 |
| HotpotQA | RAG-C-O | **0.88** | **0.10** |
| HotpotQA | RAG-C-L | 0.78 | 0.16 |
| MS-MARCO | BadChain | 0.82 | 0.82 |
| MS-MARCO | PoisonedRAG | 0.89 | 0.89 |
| MS-MARCO | AgentPoison | 0.85 | 0.85 |
| MS-MARCO | RAG-C-O | **0.89** | **0.15** |
| MS-MARCO | RAG-C-L | 0.76 | 0.18 |

最关键的观察不是 RAG-C 的 VSR 绝对最高，而是：

> 它在维持相近触发率的同时，把“触发水印就答错”变成了“触发水印但答案大体仍正确”。

传统基线里 VSR 与有害度几乎相同，是因为每次成功触发通常就意味着成功诱导错误答案。RAG-C 则把二者明显分离。

### 7.2 所有权判断（表 2）

作者测试三种场景：

1. **Ind.-C**：查询一个使用不同水印推理链的系统；
2. **Ind.-R**：查询无辜的独立 RAG；
3. **Malicious**：查询使用受保护知识库的可疑 RAG。

结果为：

| 数据集 | 方法 | Ind.-C p 值 | Ind.-R p 值 | Malicious p 值 |
|---|---|---:|---:|---:|
| NQ | RAG-C-O | 1.00 | 1.00 | \(10^{-8}\) |
| NQ | RAG-C-L | 1.00 | 1.00 | \(10^{-8}\) |
| HotpotQA | RAG-C-O | 1.00 | 1.00 | \(10^{-8}\) |
| HotpotQA | RAG-C-L | 1.00 | 1.00 | \(10^{-6}\) |
| MS-MARCO | RAG-C-O | 1.00 | 1.00 | \(10^{-8}\) |
| MS-MARCO | RAG-C-L | 1.00 | 1.00 | \(10^{-6}\) |

按 \(\alpha=0.01\) 判断，实验中无辜系统全部不被判侵权，使用受保护知识库的系统全部被识别。

但 p 值不是“侵权概率”。例如 \(p=10^{-8}\) 的含义是：在原假设成立且统计模型正确时，观察到如此极端数据的概率很小；它不等价于“系统有 99.999999% 的概率侵权”。

### 7.3 对普通问题的影响（附录表 7～9）

作者随机取 500 对未见、无关的普通问题测试准确率：

- NQ：水印前后约 0.70～0.73；
- HotpotQA：约 0.79～0.82；
- MS-MARCO：约 0.81～0.84。

绝大多数数值与未加水印时相同，个别只差 0.01。说明低比例注入没有明显破坏普通查询性能。

### 7.4 跨检索器迁移（表 3 / 附录表 10）

RAG-C-O 用 Contriever-MS 优化，却在 Contriever 和 ANCE 上测试：

- Contriever 平均 VSR：0.893；
- ANCE 平均 VSR：0.875。

这表明优化水印不完全依赖某一个检索器，能够跨模型迁移。但论文只测试了三个稠密检索器，没有覆盖 BM25、混合检索、重排序器、检索查询改写等更复杂的生产级配置。

### 7.5 水印长度和位置（图 3）

- 水印从 4 个词增加到约 7～10 个词时，VSR 明显上升后趋于饱和；
- 水印越长，越容易被发现，因此有效性和隐蔽性需要权衡；
- 放在句末通常比放在句首更有效，作者推测句末短语对检索向量的影响更大。

这只是实验观察，不是已被严密证明的通用规律。

### 7.6 不同知识库之间迁移（附录表 11）

作者把 NQ 的验证问题与 CoT 注入 HotpotQA，并额外加入 NQ 中每个验证问题的 top-5 近邻文本。水印比例不超过 0.03%，平均 VSR 仍为：

- RAG-C-L：0.825；
- RAG-C-O：0.893。

这说明验证样本可以迁移到语义无关的知识库。但额外搬运近邻文本本身也是维持效果的条件，因此不能简单理解为“无需任何调整即可跨库迁移”。

## 8. 自适应攻击：攻击者知道有水印后怎么办？

论文测试两种清洗策略。

### 8.1 困惑度过滤（PPL Filter）

罕见词组成的水印往往让句子困惑度升高。攻击者可用语言模型检测不自然文本并过滤。

结果：

- RAG-C-O 平均 VSR：0.543；
- RAG-C-L 平均 VSR：0.435。

### 8.2 问题改写（Rephrasing）

攻击者先改写用户问题，可能把水印短语删掉或替换。

结果：

- RAG-C-O 平均 VSR：0.623；
- RAG-C-L 平均 VSR：0.415。

### 8.3 应怎样评价这些数字？

作者强调它们明显高于没有水印时的 0%，因此称方法对攻击具有抗性。这一说法在相对意义上成立，但从部署角度还要看到：

- RAG-C-O 从约 0.89 降到 0.54～0.62；
- RAG-C-L 从约 0.76～0.83 降到约 0.42；
- 攻击使触发率损失了很大一部分。

因此，更准确的结论是：**水印没有被两种简单清洗完全消除，但鲁棒性仍是明显短板。** 论文也没有测试知识库去重、摘要重写、向量重编码、检索结果过滤、删除异常文体、重新构建索引或多轮水印探测等更强攻击。

## 9. 这篇论文真正有价值的地方

### 9.1 把保护对象从“模型”转向“RAG 知识库”

很多水印研究保护的是训练数据、模型参数或生成内容。本文直接关注外置知识库，这更贴近 RAG 服务中的现实资产。

### 9.2 把水印行为从“答案空间”移到“解释空间”

这是最有启发性的贡献。作者意识到，所有权水印不一定要让模型输出错误标签；只要能在某个可观测空间中形成稳定、秘密、可统计验证的差异即可。

### 9.3 面向严格的黑盒、文本接口

验证者不需要读取可疑系统的数据库、检索结果、模型参数或概率。这使方案更接近真实 API 审计场景。

### 9.4 不是只看命中率，而是引入统计检验

通过成对查询与假设检验，作者试图减少验证题抽样和阈值选择带来的偶然性。虽然命题公式存在疑点，但“用多题、成对、统计化验证”的研究方向是正确的。

### 9.5 实验覆盖比较完整

论文覆盖：

- 三个大规模知识库；
- 四种 LLM；
- 三种检索器；
- 两种水印生成方式；
- 普通准确率、跨检索器迁移、跨知识库迁移；
- 水印长度、位置、目标 CoT 修改；
- 两种自适应攻击。

对于一个提出新问题和新范式的工作，这样的实验面较广。

## 10. 局限与值得质疑之处

### 10.1 只能追踪，不能阻止盗用

这是作者在附录 H 主动承认的第一项限制。RAG-C 不能加密知识库，也不能阻止复制，只能在事后对可疑 API 进行验证。

### 10.2 依赖模型输出解释信息

如果可疑服务只返回简短答案、不输出理由，或者主动要求模型隐藏解释，目标 CoT 信息可能无法从文本接口中观察。论文的 RAG 提示让模型基于上下文回答，却没有充分讨论“仅答案接口”这一常见限制。

### 10.3 这里的 CoT 不是可验证的内部真实推理

系统复现某段解释，只能说明目标文本大概率进入了上下文并影响输出，不能证明那就是模型内部真实的因果推理过程。“reasoning”在本文中更像可观测的解释内容或理由风格。

### 10.4 GPT-4 同时承担多个关键角色

GPT-4 被用于：

- 生成两条推理链；
- 生成罕见水印短语；
- 修改目标推理链；
- 判断回答是否包含目标信息。

这使系统方便，但也带来成本、版本漂移、可重复性和裁判偏差。若裁判模型升级后判断标准变化，历史验证结果可能难以复现。

### 10.5 “无害”是相对的

RAG-C 的 \(H\) 仍为 0.09～0.22。对于医疗、法律、金融等高风险领域，这个错误比例不能简单视作可忽略。此外，论文主要把有害度定义为“答案是否正确”，没有测量解释中是否混入误导信息。

### 10.6 水印短语可能被发现

LLM 生成的短语通常带有“within the realm of ...”“under the lens of ...”等不常见文体。论文自己也观察到水印越长越有效但越不隐蔽，且困惑度过滤能显著降低 VSR。

### 10.7 每题单独优化，扩展成本高

作者承认每个验证问题和对应目标 CoT 都要优化。RAG-C-O 每题 1000 次优化迭代，若需要大量独立水印、定期轮换或为不同客户生成不同指纹，成本会明显增加。

### 10.8 统计命题写法存在疑点

前文已说明，命题 3.3 中“求和”与期望触发模式不一致。论文也只给最终 p 值，没有给检验统计量、样本配对明细、置信区间和多重检验处理方式，读者难以独立审计。

### 10.9 攻击模型仍不够强

只测试 PPL 过滤和问题改写，还没有覆盖攻击者能够访问复制知识库时可能进行的系统清洗。真正的知识库窃取者往往可以批量重写、摘要、去重并重新嵌入全部文本。

### 10.10 现实版权证据链尚未建立

统计水印证据能辅助技术判断，但能否成为法律上的版权或侵权证据，还涉及：

- 验证问题和水印生成时间的可信存证；
- 知识库所有权本身的证明；
- 水印是否可能被独立生成；
- 查询日志是否完整且未被修改；
- 假阳性率在真实开放环境中的估计。

论文没有讨论完整的法律和审计流程。

### 10.11 仅研究纯文本场景

附录 H 明确指出，方法不能直接扩展到视觉语言模型等多模态场景。

## 11. 如果要复现，最小实现路线是什么？

下面是一条基于论文的工程化路线，不等同于作者官方代码。

### 步骤 1：准备验证集

- 从知识库领域挑选约 100 道中等复杂度问题；
- 每题准备唯一正确答案；
- 让人工或强 LLM 生成两条内容独立、都支持正确答案的解释；
- 人工审核事实正确性和差异性。

### 步骤 2：生成客户专属水印

- 快速方案：让 LLM 生成 2～10 个罕见但不改语义的词组；
- 高效果方案：用替代检索器做离散 token 优化；
- 水印应尽量因题而异，不宜所有题共用一个触发短语；
- 为每个发布对象生成不同水印，便于追踪泄漏来源。

### 步骤 3：改写目标解释

- 保持正确答案和核心事实不变；
- 改写主语、句法和词汇；
- 让其靠近带水印查询、远离原始查询；
- 人工复核，避免为了向量距离制造错误或怪异信息。

### 步骤 4：注入知识库并测试

- 每道题加入带水印目标解释和普通非目标解释；
- 在真实检索器上检查 top-\(k\) 命中情况；
- 计算带水印问题的目标命中率；
- 计算原问题误触发目标解释的假阳性率；
- 测试普通问答准确率是否下降。

### 步骤 5：建立可审计验证协议

- 固化验证题、水印、时间戳和知识库版本；
- 使用未公开的验证题子集；
- 对可疑系统逐题发出成对查询；
- 保存完整请求、响应、时间和接口信息；
- 由至少两种判别器或人工复核目标信息是否出现；
- 除 p 值外，同时报告效应量、置信区间、假阳性率和原始配对结果；
- 预先规定检验方法与阈值，避免看完结果再挑统计方法。

### 步骤 6：进行更强的红队测试

- 查询改写；
- 困惑度过滤；
- 知识库全文摘要与重写；
- 去重和异常文体检测；
- 更换嵌入模型；
- 混合检索和重排序；
- 只输出短答案；
- 检索上下文脱敏或压缩。

只有在这些条件下仍能稳定验证，才更接近实际可部署方案。

## 12. 论文与成员推断攻击（MIA）的区别

附录 G 解释了为什么作者不采用成员推断攻击作为知识库所有权证明。

成员推断试图判断某个样本是否属于模型使用的数据。问题是，它通常利用数据本身已有的特征；语义相似的文本可能被误判为成员。对 RAG 来说尤其麻烦，因为 LLM 的预训练数据、微调数据和外置知识库都可能包含相似知识，很难确认信息究竟来自哪一层。

RAG-C 则主动加入外部、秘密特征：只有受保护知识库应当包含特定的水印短语与目标解释组合。理论上，这种人为设计的唯一性比数据原生特征更适合作为所有权指纹。

但“唯一性”仍需现实验证：如果水印短语是通用的稀有表达，或其他模型也可能独立生成相似解释，就仍有假阳性风险。因此实际部署应采用大量、随机、客户专属的组合，并进行时间戳存证。

## 13. 我对这篇论文的总体评价

### 13.1 它解决得比较好的问题

论文很好地提出了一个此前关注不足但很现实的问题：**RAG 的知识库被复制后，拥有者怎样只通过文本 API 证明对方在使用它？**

它最有价值的思想，是把后门水印的异常行为从“错误答案”转移到“不同但仍正确的解释”。这一转移简单、直观，而且实验上确实显著降低了有害度。作为一个开题式工作，它明确了问题、给出端到端方案，并通过多数据集、多模型和多检索器实验证明了可行性。

### 13.2 它还没有解决好的问题

方法距离强对抗、真实生产环境和法律取证还有距离：

- 服务方若不输出解释，验证可能失效；
- 知识库全文清洗和改写尚未测试；
- 判别高度依赖 GPT-4；
- 统计命题疑似有符号错误；
- “无害”只是相对降低错误，不是零伤害；
- 只覆盖文本 RAG 和少数稠密检索器。

所以，这篇论文更适合被理解为：

> 它提出并验证了一种有潜力的 RAG 知识库所有权指纹范式，而不是已经给出可以直接用于司法认定、且对强攻击稳健的成熟版权系统。

### 13.3 推荐怎样记住它？

只记住下面四句话即可：

1. **保护对象**：RAG 外部知识库，而不是 LLM 参数。
2. **核心创新**：最终答案不变，把水印藏在可观察的解释/推理信息中。
3. **验证方式**：原问题与带水印问题成对查询，再做统计检验。
4. **主要短板**：强清洗、只返回短答案、裁判模型依赖和统计细节仍未解决。

## 14. 术语速查表

| 术语 | 简单解释 |
|---|---|
| RAG | 先从外部知识库检索，再让 LLM 基于检索内容回答 |
| Knowledge Base | RAG 的外部文本库，可能包含私有或高价值知识 |
| Retriever | 把问题映射为向量并找出相似文本的模块 |
| CoT | 本文语境下主要指回答中可观察的理由/解释链 |
| Target CoT | 带水印问题希望触发的特殊解释 |
| Non-target CoT | 原始问题使用的普通解释 |
| Watermark Phrase | 追加到验证问题和目标解释中的秘密罕见短语 |
| RAG-C-O | 用替代检索器和梯度优化生成水印的版本 |
| RAG-C-L | 用强 LLM 直接生成水印短语的版本 |
| VSR | 验证问题成功触发目标解释的比例 |
| Harmfulness \(H\) | 验证过程中最终答案错误的比例 |
| False Positive | 无水印原问题也触发了目标解释 |
| Black-box | 只能通过输入输出访问系统，看不到内部组件 |
| Wilcoxon Test | 比较成对样本差异的非参数统计检验 |
| p 值 | 原假设成立时，出现当前或更极端数据的概率；不是侵权概率 |

## 结语

RAG-C 的想法可以用一句通俗的话结束：

> 传统水印让系统“看到暗号就故意答错”；RAG-C 则让系统“看到暗号仍答对，但用只有知识库拥有者预先埋下的特殊理由来回答”。

这种做法显著减少了水印对系统功能的伤害，也为黑盒验证 RAG 知识库所有权提供了一个值得继续研究的方向。理解这点，就抓住了整篇论文的核心。
